## Active delivery ledger — 2026-08-13

This is the operational view of the roadmap. `R0.md` remains the evidence
baseline, `R1.md` the full capability catalog, and `R3.md` the provider/decision
register. Update this ledger only when a tier blocker is resolved, a tier moves
between `blocker_resolution`, `building`, and `verifying`, the complete tier is
promoted ProductUseful, or T6's explicit `track_partial` inventory/missing-scope
record changes without claiming blocker exit or delivery progress.

There is no active plugin-level queue and no new Experimental-complete
milestone. Existing package slices are inventory. Focused tests are inner-loop
diagnostics; the expensive matrix and promotion happen once per tier through
`bun run tier:verify -- Tn`.

Provider breadth and production credentials are not tier blockers. Each product
defines a stable provider capability plus focused adapter conformance tests and
can add mainstream adapters later without changing its domain/Pi contract.
Caller-owned credentials enter only through documented runtime environment or
injected capabilities and may be used by opt-in live tests; they are never part
of the product. Only absence of any testable path blocks delivery. At present,
that external condition applies only to T6 real-time market behavior.
